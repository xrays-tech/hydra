Hydra Terminate Mode

A high-performance LLM routing gateway on Pingora — the runtime request-handling workflow in terminate-in-Pingora mode. The gateway terminates the request inside request_filter, calls the provider with its own reqwest client, and streams the SSE response back — returning Ok(true) so Pingora never dials upstream.

Key policies

The guarantees and trade-offs encoded across the terminate-mode pipeline.

Terminate mode

Reads the full body in request_filter → model at any position → reqwest call to the provider → SSE stream-back via session.write_response_body. Returns Ok(true).

Routing

model ∩ TenantModel-gate ∩ online providers ∩ tenant-allowed. Nginx SWRR weighted round-robin orders the candidates.

Failover

A plain for loop with Bytes::clone() O(1) replay. No Pingora retry mechanism — no set_retry, no buffer truncation.

Circuit breaker

N consecutive failures → provider enters the dead-set and is skipped. A background probe revives it once it heals.

Rate limit

In-memory sliding window — count pre-flight + tokens post-flight, across m / h / d windows.

Usage

5 token dims (prompt / completion / total / cached / default-0) + 2 latency dims (forward_latency / TTFT). Sink to SQLite (default) or ClickHouse.

Auth

Cache-first, 5-min TTL. Denials cached with a short TTL. DELETE /api/v1/auth/cache forces re-auth on the next request.

TLS

SNI-based per-tenant certificate (BoringSSL callback) with hot-reload — no restart needed to rotate certs.
